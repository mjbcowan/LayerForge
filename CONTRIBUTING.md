# Contributing to LayerForge

LayerForge is a napari plugin wheel that reads images into [SpatialData](https://spatialdata.scverse.org) objects. That puts it inside two ecosystems with established testing conventions: napari's plugin ecosystem and scverse.

## Setup

```bash
python -m venv .venv           # or: uv venv
.venv/bin/pip install -e ".[dev]"
```

## Running the tests

```bash
pytest
```

**On macOS, do not set `QT_QPA_PLATFORM=offscreen`.** CI sets it because it runs on Linux with a headless GL display installed alongside it. On macOS the offscreen platform provides no OpenGL context, so napari's canvas setup (`napari._vispy.utils.gl.get_max_texture_sizes`) segfaults the interpreter the moment a viewer is created — which looks like a broken test suite but is only a misconfigured display. Plain `pytest` works.

The npe2 manifest is validated separately, as CI does:

```bash
python -m npe2 validate src/LayerForge/napari.yaml
```

## Testing conventions

New code is expected to be covered by the categories below. 

### 1. Test the reader through its contract, not its internals

A napari reader plugin's public contract is: `napari_get_reader` returns a callable, that callable returns a list of `(data, kwargs, layer_type)` tuples, and the pixels survive. This is the shape generated by the [napari-plugin-template](https://github.com/napari/napari-plugin-template).

**Assert on pixel values, not just array shapes.** Checking `sizes["y"]` and `sizes["c"]` lets a reader that transposes axes or returns zeros pass. Use `np.testing.assert_array_equal` against the array that was written to disk.

See `test_reader_returns_layer_data_tuples_and_preserves_pixels` in [tests/test_reader.py](tests/test_reader.py).

### 2. Exercise the real plugin dispatch path

Unit-testing `load_image_as_sdata` is not the same as opening a file in napari. `viewer.open(path, plugin="LayerForge")` goes through npe2 manifest discovery, command resolution, `ReaderContribution.exec`, and napari layer construction.

Previously, a crash shipped in exactly that gap once: a filename containing spaces was used verbatim as a SpatialData element name, which SpatialData rejects. Every direct unit test passed. Anything touching the reader, the manifest, or layer metadata needs a test in [tests/test_plugin_integration.py](tests/test_plugin_integration.py).

### 3. Use napari's own viewer fixture

napari ships `make_napari_viewer` and `make_napari_viewer_proxy` as a pytest plugin (a `pytest11` entry point on `napari.utils._testsupport`), so they are available with no conftest wiring. Use them rather than constructing `napari.Viewer(show=False)` by hand — they handle Qt app setup and teardown and fail tests that leak viewers or widgets.

### 4. Round-trip SpatialData objects through zarr
 
`spatialdata.testing` provides `assert_spatial_data_objects_are_identical`, `assert_elements_are_identical`, and friends. Any code that constructs or transforms a SpatialData element should assert it can be written and read back:

```python
sdata.write(zarr_path)
assert_spatial_data_objects_are_identical(sdata, spatialdata.read_zarr(zarr_path))
```

This is not ceremony. SpatialData restricts element names precisely because they become group paths inside the zarr store, so a write round-trip is the honest test of whether a name is usable. Also assert produced elements are well-formed with `get_model(element)` and `Image2DModel.validate(element)`.

### 5. Use property-based tests for pure functions with invariants

Where a function has a stateable invariant, assert the invariant over generated input rather than a handful of hand-picked cases, and use the upstream library as the oracle where one exists:

```python
@given(hyp_st.text())
def test_sanitize_element_name_always_produces_a_valid_name(raw):
    check_valid_name(_sanitize_element_name(raw))
```

That is strictly stronger than enumerating cases, and it fails loudly if SpatialData tightens its naming rules underneath us.

### Warnings are errors

`pyproject.toml` promotes LayerForge's element-rename warning to an error, so a
test that triggers an unintended rename fails instead of printing to the
console. Tests that expect the warning must opt in with `pytest.warns`.

Note the filter matches on the warning *message*, not the module: `warnings.warn(...,
stacklevel=2)` attributes a warning to the calling module, so a
`:LayerForge._reader` module filter silently never fires.

## Coverage

CI enforces a floor via `coverage report --fail-under`, configured in
`[tool.coverage.report]`.

The suite is at 94%; the gate is 90%, deliberately a few points below so that
unrelated churn does not turn CI red on its own while a genuine regression still
does.

| module | coverage |
| --- | --- |
| `annotate_sdata.py` | 99% |
| `_reader.py` | 93% |
| `_widgets.py` | 93% |
| `sdata_utils.py` | 90% |
| `sample_data.py` | 45% |

`sample_data.py` is the remaining gap: `load_skin_sample` calls
`skimage.data.skin()`, which downloads via pooch, so covering it would make the
suite require network access. Left uncovered on purpose.

**Ratchet policy: `fail_under` only ever goes up.** When coverage rises
durably, raise the floor in the same PR. Never lower it to make a build pass —
add the tests instead.

### What the annotate_sdata.py gap was hiding

That module sat at 29% until the tests in
[tests/test_annotate_sdata.py](tests/test_annotate_sdata.py) were written. Doing
so surfaced four bugs in code that had never been executed by a test, which is
the argument for the floor in the first place:

- `measure_label_morphology` put `instance_id` on `obs` as both the index name
  and a column, so `spatialdata.join_spatialelement_table` raised
  `ValueError: cannot insert instance_id, already exists`.
- `labels_to_shapes` left its GeoDataFrame on a default `RangeIndex`, so even
  after that fix only some regions matched. SpatialData treats a shapes
  element's index as its instance key.
- Three single-scale fallbacks caught `(TypeError, AttributeError)`, but
  indexing a plain `DataArray` with `["scale0"]` raises `KeyError` — so the
  fallback was dead code and any non-pyramidal image crashed. `_reader.py`
  produces single-scale elements for images at or below 256px.
- `run_annotation_session` read `viewer.layers` from a callback on the Qt
  window's `destroyed` signal, by which point napari has emptied the layer
  list, so the documented `sdata.attrs["contrast_limits"]` capture was always
  `{}`.

The README badge is served by [Codecov](https://codecov.io/gh/mjbcowan/LayerForge),
configured in [codecov.yml](codecov.yml). Codecov reports but never gates: its
status checks are `informational: true` so a PR does not collect two competing
red checks for one cause. The gate is the `Enforce coverage floor` CI step.
Note that CI uploads to Codecov *before* running that gate, so the badge and the
coverage artifact still update on a build that the floor fails.

If you raise `fail_under` in `pyproject.toml`, update `target` in
`codecov.yml` to match.

## Pull requests

The [PR template](.github/pull_request_template.md) carries a checklist keyed to
the conventions above. CI runs, in order:

1. `npe2 validate` on the plugin manifest
2. the full test suite (Python 3.11 and 3.12)
3. the coverage floor, as a separate step so a coverage shortfall is never
   mistaken for a test failure
